# Execution rules
Adapted from Lemomo/LemoLab Lemo-Opuscar TECHNIQUE.md; MIT/CC BY 4.0, see ATTRIBUTION.md.
1. Treat film JSON as the single timeline: scenes occur sequentially; narration and music cue times are seconds. Use film-schema.json and renderer validation before work.
2. Offline: inspect capabilities, never attempt network installs. Use Pillow/numpy via renderer-py/render.py. Each Scene exposes render(t) in local scene time. Seed randomness; frames must render independently. No browser, WebGL or TTS. Use captions or a local uploaded voice file. If MP4 encoding is unavailable, return frames, WAV and SRT and state the limitation.
3. Action: call getStyles, submitFilm, poll getJob, then return the temporary download_url. Never send arbitrary HTML/JS, asset URLs or local file paths. API credentials belong in Action authentication, never in chat.
4. Prefer the 18 semantic templates described in EDUCATION.md, with studio, midnight, paper, ocean, coral or violet themes. Five legacy object styles remain available: swiss-motion, blueprint, chalkboard, woodcut, pixel-rpg. Other upstream catalog prompts are reference only. WebGL is an optional server compositing pass, not a promise of arbitrary 3D scenes.
5. Generate original numpy music from cue events. Server TTS is local eSpeak, not a cloned or expressive neural voice. Check that spoken lines fit their scene; shorten and reconfirm if they do not.
6. Check actual encoded duration, dimensions, video/audio streams and frames. Inspect contact sheets. No stock footage or video generation models. Preserve Lemomo/LemoLab attribution and original license notices.
