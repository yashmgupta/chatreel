# GitHub discovery settings

Repository files improve the landing page. GitHub's About description, topics and social preview are separate settings; changing a README does not update them.

## Suggested About text

ChatGPT to code-rendered short films: offline Python or a self-hosted GPT Action, with five visual styles, procedural music and MP4 export.

## Suggested topics

`chatgpt`, `custom-gpt`, `gpt-actions`, `code-interpreter`, `text-to-video`, `code-rendered-video`, `generative-art`, `animation`, `python`, `pillow`, `fastapi`, `playwright`, `ffmpeg`, `self-hosted`

The description and README must make clear that this is code-rendered animation, not a video-generation model. Use topics that describe actual features.

A repository owner can set these from the gear icon beside **About** on the repository home page. Keep the website field empty unless there is a real project site or hosted app.

## Sustainable ways to share

1. Make one useful original short film and share its MP4 alongside the reproducible film JSON.
2. Share the repository in relevant communities when their posting rules allow it. Show the actual result, limitations and a short setup path.
3. Invite compatibility reports and small contributions; improve the first-use experience from that feedback.
4. Publish a GitHub release when its version and artifacts are ready. Do not advertise an unreleased or untested hosted service.

A clear landing page and useful examples help people assess the project; they cannot guarantee adoption.
